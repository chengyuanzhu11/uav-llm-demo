# 校园任务框架

用户通过 `POST /api/mission/task` 提交 `{"instruction":"自然语言任务或调整要求"}`。DeepSeek 读取空间与能力目录、任务上下文，生成包含步骤、条件、分支、循环、通用控制与执行评估的任务程序。本地执行器解析目标并推进任务，几何规划器负责转场，连续轨迹执行器与控制器负责飞行和避障；任务以实际达到用户要求的结束状态为完成依据。推荐任务只是示例，不是命令白名单。

## 条件与循环

条件可比较实际观测中的数值、布尔值和字符串，支持 `< <= == != >= >`、与/或/非组合。数值条件可自行设置阈值，例如“图书馆温度超过 25℃就采样”，无需使用默认的热异常阈值。可引用其他地点已经产生的观测；不能引用未来、可能被跳过的观测，或不存在的传感器字段。

循环可指定次数，也可在每轮执行后检查退出条件；次数和条件同时指定时，任一满足即可结束。持续循环可在执行中修改为返航。分支在进入时依据当时已有的数据选择一个路径，不会把没有执行的路径标成完成。电量来自仿真遥测，`elapsed_seconds` 从当前生效修订开始执行时归零，暂停期间仿真时间仍累积。

条件在任务切换或每轮结束时求值；当前不支持飞行航段内持续监测条件并立即中断。用户主动提交的任务修改会立即停止旧任务推进，并在新要求通过解释和校验后执行。

定点技能为访问、巡检、模拟热检查、模拟采样和返航降落，另有可组合的通用位置控制、空间运动与执行评估节点。原定点技能的默认驻留时间为 0/2/3/1/0 秒，显式的正观测时长可以小于默认值。热读数仍是仿真场景中的预设数据；没有增加真实热成像、人员检测、运输或照片生成能力。

## 通用控制与空间查询

`control` 统一表达前往某处并达到指定状态：地点的几何中心或安全抵达点、相对米制偏移、可选高度、朝向、停留时间，以及地面停驻或空中保持。DeepSeek 将用户描述组织为这些可组合的参数，本地空间查询器从共享地图解析实际位置。建筑与场地的中心、室外抵达点、几何边界各有独立含义；“到场地中央”不会替换成该地点的室外访问点。

降落由地表几何、可用净空、障碍物和任务安全限制共同检查，不按地点名称建立专用动作。地面目标必须有当前模型支持的可用地表，并通过抵达、下降通道和接地检查；建筑内部、水面、净空不足的位置不能因为模型输出了坐标就执行。局部起降许可仅覆盖已验证的作业位置，巡航限高、避让区域、建筑间距和动态避障继续有效。低于巡航下限的悬停也需要同样的已验证垂直通道，地点之间的转场仍先爬升至安全巡航高度。

同一个控制接口可以完成“去北区足球场中央降落停留，不用返航”“在南广场中央停留后继续去其他地点”“在目标附近指定高度保持位置”等任务。前两者使用相同的空间查询与地面状态转换，第三者使用空中状态；执行器无需为每条自然语言增加新的任务类别。停留时间表示到位并稳定后的驻留时间，不能把转场或下降时间计入停留。

程序不再要求末步必须为 `return_home`。最终目标记录位置和地面／空中状态，完成时核对实际位置、速度与接地情况；仅经过目标上空不能完成地面停驻任务。任务在空中结束时，本地控制继续保持位置并执行安全保护。返航仍可由用户安排，也仍是安全处置可用的行动。

## 空间运动程序

用户仍输入自然语言，例如“沿田径场顺时针飞行两圈后返航”或“第二圈逐渐升高，机头始终朝向场地中心”，无需输入坐标、表达式或底层字段。DeepSeek 生成 `motion` 节点，并可将其放入现有条件、分支和循环；本地编译器根据共享地图计算可执行轨迹。

运动路径统一支持三种表达：

- `boundary`：沿实体提供的真实边界或中心线飞行，指定方向、圈数与起止高度；田径场的显示和规划共用跑道中心线。没有边界数据的地点不能假定为圆形。
- `curve`：以地点的空间锚点为原点，用参数 `t`、`pi`、`sin`、`cos` 和有界四则运算表达三维曲线，可组合八字、螺旋或其他曲线。表达式由受限语法树解释，不使用 `eval`，不运行模型生成的任意代码。
- `polyline`：按顺序连接相对于地点锚点的米制三维点，用于一般折线形状。

相对坐标为 x 向东、y 向南、z 向上，原点高度使用地点作业高度；`boundary` 的高度参数为距地面的绝对米数。默认速度 2.5 m/s、朝向沿运动方向；也可固定机头朝向或持续面向指定地点。机头朝向与平移独立，北为 0°，顺时针为正。未指定的高度和方向使用目录中的默认值。

转场允许安全缩短路径；任务轨迹保持规定顺序和方向，连续跟踪而非逐点停车。进度依据实际运动覆盖的轨迹区段累计，不能凭终点到达确认绕行完成；闭合曲线和重复圈数仍必须经过全部规定区段。避障后继续尚未完成的区段，任务完成记录包含 `completed`、`distance_m`（轨迹覆盖距离）、`total_length_m` 和 `progress`。覆盖距离不是包含所有避障绕行的累计飞行里程。

单段运动最多 2048 个采样点、3000 米，边界绕行最多 20 圈，速度范围 0.1–4 m/s；采样密度同时考虑曲线变化，不能通过少量采样漏掉高频轨迹。表达式、轨迹长度、建筑安全间距、限高及避让区均在执行前校验。可表达运动组合不等于具备未实现的传感器、运输能力或任意机动性能。

## 飞行中修改

用户可直接提交“先去图书馆”“取消剩余任务并返航”等调整。新指令解释期间，停止旧任务推进，制动等待并继续本地避障；不重置位置、速度、世界时间、交通种子、轨迹、电量或已完成记录。模型收到原生效指令、当前及剩余步骤和已产生的证据，输出完整的新剩余程序。

新程序通过能力、类型和路径检查后一次切换。已经生成的所有分支和循环回边都进行静态预检；解释过程中当前位置变化时，还会检查最新位置是否符合新限制，必要时在后台重新预检，不额外调用模型。如果新限高或新避让区排除了当前位置，则保留原限制安全等待，不直接套用限制使控制器硬停。

每次接受任务或澄清结果递增 `revision`，实际生效计划记录 `plan_revision`。历史记录保留各自修订号、唯一 `execution_id/evidence_id` 和循环次数。新步骤的同名 ID 不会读取旧修订结果，只有明确的历史证据 ID 可用于历史条件。新要求被拒绝时不会自动恢复旧任务；可继续提交调整或要求返航。暂停、重置和换地图会使旧的异步回复失效。

## 执行反馈与任务评估

`review` 使模型能在执行中依据观测重新评估后续任务。用户提出“根据检查结果决定下一步”之类要求时，模型可把评估节点放在观测之后，也可配合分支或循环触发；执行到该节点时，将最新遥测、实际执行证据与尚未完成的任务交给 DeepSeek，由它重新组织剩余程序。条件求值、轨迹跟踪和本地避障仍在本地连续执行。

评估期间维持安全等待，模型的新程序仍须通过能力、类型、空间和路径检查；自主评估保持原任务明确指定的最终目标（包括朝向、驻留时长或末段运动要求）与硬约束，不能自行放宽安全限制或把用户要求的地面停驻改成经过上空。未限定后续行动的开放任务可以以评估节点结束当前程序，再由模型根据已有观测选择后续程序，无需预设返航终点。每条用户指令最多进行 8 次自主评估，避免无限调用；后续用户修改可以重新安排任务。

`execution_feedback` 保留关键执行反馈，任务界面沿用现有提示展示解析、评估及执行结果，不另设复杂面板。`goal_state` 记录目标位置、要求的地面／空中状态及是否经过遥测确认。完成提示随实际终态显示降落停驻或保持位置，不一律称为返航完成。

## 能力与资源边界

执行器只接受地图公布的地点、技能、可观测字段和受限空间表达，不执行任意生成代码。结构最多 128 个节点、8 层嵌套，定点动作驻留最长 600 秒；同一任务累计最多 1024 次技能调度、1000 次循环迭代，修改任务不清零预算。达到预算或缺少必需观测时进入安全等待，不能标成成功；此时仍允许修改任务。位置、速度、限高、净空和地表等约束统一作用于所有地点及程序组合。

任务目录发布与本地结构校验共用的 `task_program_schema`，覆盖动作、运动路径、位置控制、条件和循环；语义与几何安全检查继续独立执行。格式错误会提供具体 JSON 路径、缺失或多余字段、允许的字段及类型。自动纠错将这些诊断连同上一版候选交给 DeepSeek，要求保留原指令及约束并修正完整程序，最多两次。候选在内存中脱敏并限制为 32000 字符，超限时仅回传诊断，不写入运行日志或公开状态；提交新任务、重置或结束解析后清除。

初次生成和两次修正均未通过时显示“生成失败”，无人机保持安全等待，允许直接重试原指令；不会把模型格式错误显示成需要用户补充任务条件。地点不明确、能力缺失和安全冲突仍使用各自的反馈。HTTP 503 等临时传输失败继续采用现有退避重试。

这些限制用于约束程序资源和执行能力，不要求用户按固定句式输入。未说明的可选参数使用默认值；含糊地点、缺少能力或互相冲突的要求会给出具体说明。

## 验证边界

`tests/test_generic_control_service.py` 用指定足球场指令及篮球场、南广场任务验证落地、不返航、再次起飞、低空停留、执行评估与终态；`tests/test_spatial_control.py` 和 `tests/test_ground_sites.py` 验证共享空间与起降通道。`tests/test_semantic_program.py` 验证程序及证据语义，`tests/test_semantic_updates.py` 使用离线语义响应和实际几何规划、控制器验证修改、循环和返航，`tests/test_frontend_semantic_program.py` 验证任务显示、轨迹进度、通用控制、实测终态提示、执行评估及提交交互；空间编译与连续执行另由对应运动测试覆盖。离线响应证明执行链可处理相应程序，不能代替真实 DeepSeek 对任意自然语言的理解验收。

`python scripts/verify_semantic_program.py` 在实际校园建筑地图中运行计次循环、数值分支、条件退出和途中改派，使用离线接口响应并暂不放入鸟群，以单独验证任务执行；报告默认输出到 `outputs/semantic-program/campus-flights.json`，不接触当前 Flask 服务。

`tests/test_task_protocol.py` 检查共享协议、嵌套字段诊断和默认值；`tests/test_semantic_repair.py` 验证自动纠错、任务之间的候选隔离及候选保密，并使用离线 API 响应完成东侧花园和西侧花园的整圈飞行、返航与降落，防止为单个地点添加特例。
