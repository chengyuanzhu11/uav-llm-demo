# 校园任务框架

用户通过 `POST /api/mission/task` 提交 `{"instruction":"自然语言任务或调整要求"}`。DeepSeek 读取空间与能力目录、任务上下文，生成包含步骤、条件、分支、循环、通用控制与执行评估的任务程序。本地执行器解析目标并推进任务，几何规划器负责转场，连续轨迹执行器与控制器负责飞行和避障；任务须同时满足已接受的完整要求与实测结束状态才能完成。推荐任务只是示例，不是命令白名单。

## 条件与循环

条件可比较实际观测中的数值、布尔值和字符串，支持 `< <= == != >= >`、与/或/非组合。数值条件可自行设置阈值，例如“图书馆温度超过 25℃就采样”，无需使用默认的热异常阈值。可引用其他地点已经产生的观测；不能引用未来、可能被跳过的观测，或不存在的传感器字段。

循环可指定次数，也可在每轮执行后检查退出条件；次数和条件同时指定时，任一满足即可结束。持续循环可在执行中修改为返航。分支在进入时依据当时已有的数据选择一个路径，不会把没有执行的路径标成完成。电量来自仿真遥测，`elapsed_seconds` 在用户新指令生效时归零，自主评估保持同一任务时钟，暂停期间仿真时间仍累积。

条件在任务切换或每轮结束时求值；当前不支持飞行航段内持续监测条件并立即中断。用户主动提交的任务修改会立即停止旧任务推进，并在新要求通过解释和校验后执行。

定点技能为访问、巡检、模拟热检查、模拟采样和返航降落，另有可组合的通用位置控制、空间运动、视觉反馈与执行评估节点。原定点技能的默认驻留时间为 0/2/3/1/0 秒，显式的正观测时长可以小于默认值。任务世界按独立种子生成温度与异常，模型只接收实际交付的读数；传感器可配置噪声、丢失、延迟及冲突。观测携带来源、时间、置信度和有效期；未知、冲突、过期都不能完成观测任务。传统 `capture` 仍是模拟记录；新的 `visual` 节点使用实际渲染的机载图像，不代表真实热成像、人员检测或物理相机验收。

## 机载观测与持续反馈

`visual` 是通用的外观寻找／接近义务，形式为 `{id,action:"visual",target_id,visual:{description,max_distance_m},when}`。`target_id` 指已知的搜索起始地点，用户未指定时由计划选择，不冻结到原始要求；`description` 保存用户的外观条件，不能被模型自由改写。用户未指定的观察距离由计划选择，明确距离按上界校验；观察方向、短程航点和尝试次数不冻结为用户要求。它可与原来的循环、条件和返航组合，完成视觉义务不会消除后续事项。

要求提取、独立审查和规划共用开放物体搜索策略：地点目录没有列出物体，不构成“未建模／不支持”的依据，也不要求用户提供物体 ID 或坐标。物体是否存在由执行时图像决定，未找到不能声明完成。校园可测试的三类树形和多种景物见[地图说明](beihang-campus-model.md#视觉测试景物)。

协议 1.1 的 `motion`、`control` 可带 `target_ref:{step_id:"find"}`，引用本次修订中必定先完成的视觉步骤；后续用户指令或自主修复可通过 `target_ref:{evidence_id:"…"}` 引用本任务已确认的历史证据。`target_id` 此时仅保留导航区域，不能代替物体位置。物体锚点取两帧有效定位的平均值，保留观测分散程度、证据 ID、源执行实例和帧 ID，不从地图景物名称反查坐标。

相对曲线／折线以观测点为三轴原点；绕物体的参考圆保持 x/y 中心为零，未指定半径可缩放，不能自由平移到区域中心。位置控制的 x/y 偏移相对观测点，`altitude_m` 仍为绝对高度；`face_reference` 表示机头朝向该观测点。只有点定位时不能使用物体 `boundary`，它并未提供物体边界。

观测前的试算明确返回 `deferred_targets`，不会宣称尚未知位置的路径已经安全。视觉任务完成后，执行器绑定具体证据并重新生成、检查全轨迹与入场航段；不安全则走现有恢复流程。完成契约独立检查源证据、实际绑定、路径长度与终点，丢失引用、换成区域中心或复用错误修订的观测均不能验收。循环内引用最新一次对应视觉执行；历史引用保持指定证据不变。此机制定位静态物体，不等于持续跟踪移动目标。

HTML 模式由浏览器另建标定相机，不使用 Follow UAV、OrbitControls 或插值后的无人机位置。请求绑定修订号、执行实例、仿真时间和实测位置；使用理想稳定云台，朝向按世界坐标设置，尚未模拟云台响应和机体振动。320×240 RGB 与光轴深度来自同一渲染通道，带内参、相机姿态和图像／深度校验和。标签、轨迹和展示辅助物不进入观测。当前相机采集校园静态环境，鸟群仍由独立的动态观测与本地避障处理。HTML 相机需要网页保持打开；未收到图像时安全等待，不能补造观测。

Gazebo 模式由原生 RGB-D 传感器提供 640×480 图像，垂直视场为 45°。云台使用物理关节、补偿实测机体姿态，并等待新帧朝向误差在 1° 内持续 0.2 仿真秒。相机安装在机身下方中线；起降验收同时检查镜头高于地面、斜视方向的机体遮挡及深度投影。内参、裁切后的实际视场和外参均来自传感器与 Gazebo 位姿，采集无需网页保持打开；浅俯角的图像边缘仍可能包含起落架。

视觉模型只从图像报告候选、像素位置、遮挡和不确定性；原有 DeepSeek 结合这些报告、公开起始区域几何、视角历史、已完成事项及工具反馈选择 `look / probe / preview_move / submit_move / ground / wait`。隐藏目标坐标和场景答案不进入两种模型的输入。像素经同帧深度和外参投影为三维位置；最多 12 米的短程候选须预检，提交时再次按当前位置和任务约束检查，既有控制与避障继续生效。只读查询和试算保留同帧感知及工具对话，不重复调用图像模型；试算不等于执行，模型须明确提交候选。每轮感知与规划在独立工作线程中运行，已验证的当前航段继续执行，后续意图只在稳定停驻后应用；风扰下的等待也保持位置。

每个视觉义务最多 32 轮、600 秒墙钟时间，每轮最多一次图像模型和一次语言规划请求；错误与实际调用单独记录。连续六轮没有增加有效确认或减小观察距离缺口时，向规划模型报告无进展事件，日志按六轮合并；模型根据观测决定如何改变视角或位置。距离校验使用三维欧氏距离，并回传相对当前机体的米制偏移、水平／垂直分量；未满足距离的测量保留在同一轮工具对话中，避免重新感知掩盖尚未处理的反馈。图像等待上限 20 秒；回复超过 60 秒仿真时间、位置变化超过 15 米或执行实例改变会丢弃并重新观测。新指令／Reset 作废旧会话，感知返回后若任务已变更，不再发起下一次规划调用。

目标确认仅能选择当前视觉报告中的候选编号，图像、像素及置信度由程序绑定，语言规划不能重写这些感知结果；任意表面测距使用独立的 `probe`。视觉接口使用 0–999 整数坐标，按[服务商坐标约定](https://help.aliyun.com/en/model-studio/vision)转换为归一化像素，避免让语言规划再次估算位置。首次选中的候选仅用于粗定位和聚焦：相机按实测三维点瞄准，将垂直视场收到约 37.5°，更新内参后重新采集。随后须在两帧新图像中重新识别、选点，两次观测绑定执行实例、空间位置相符且达到距离要求，才产生完成证据；粗定位图不计入确认。主动改变视角或移动会重新开始确认。语义身份仍是模型判断，自报置信度不是经过校准的正确率，独立实验必须检查真实目标，不能把此门禁当作视觉识别必然正确的证明。

默认百炼视觉模型为 `qwen3-vl-plus`，语言模型沿用原配置。`VISION_MODEL` 可覆盖；同一接口复用其已有密钥，独立接口须同时设置 `VISION_BASE_URL` 与 `VISION_API_KEY`，不会把另一接口的密钥转发过去。RGB 会发给配置的视觉服务商，语言规划只收到结构化感知报告；常规运行日志保存元数据和数值证据，不保存原始图像。仍使用已知地图保护飞行，不宣称未知环境导航或 VLA-AN 的训练效果；外部仿真使用 Gazebo 的同步 RGB-D 和测得相机姿态。

条件需要已过期的读数时，执行器回到同一目标重新观测，再继续原条件。原证据保留，新的 `refresh_of` 关联只更新条件读取，不重复满足动作义务；复合条件的多个过期输入逐一复测。默认有效期为 120 秒，可在评测中独立配置。明确的旧演示世界仍可注入执行器测试，生产服务不再按地点硬编码温度。

## 通用控制与空间查询

`control` 统一表达前往某处并达到指定状态：地点的几何中心或安全抵达点、相对米制偏移、可选高度、朝向、停留时间，以及地面停驻或空中保持。DeepSeek 将用户描述组织为这些可组合的参数，本地空间查询器从共享地图解析实际位置。建筑与场地的中心、室外抵达点、几何边界各有独立含义；“到场地中央”不会替换成该地点的室外访问点。

降落由地表几何、可用净空、障碍物和任务安全限制共同检查，不按地点名称建立专用动作。地面目标必须有当前模型支持的可用地表，并通过抵达、下降通道和接地检查；建筑内部、水面、净空不足的位置不能因为模型输出了坐标就执行。局部起降许可仅覆盖已验证的作业位置，巡航限高、避让区域、建筑间距和动态避障继续有效。低于巡航下限的悬停也需要同样的已验证垂直通道，地点之间的转场仍先爬升至安全巡航高度。

同一个控制接口可以完成“去北区足球场中央降落停留，不用返航”“在南广场中央停留后继续去其他地点”“在目标附近指定高度保持位置”等任务。前两者使用相同的空间查询与地面状态转换，第三者使用空中状态；执行器无需为每条自然语言增加新的任务类别。停留时间表示到位并稳定后的驻留时间，不能把转场或下降时间计入停留。

程序不再要求末步必须为 `return_home`。最终目标记录位置和地面／空中状态，完成时核对实际位置、速度与接地情况；仅经过目标上空不能完成地面停驻任务。任务在空中结束时，本地控制继续保持位置并执行安全保护。返航仍可由用户安排，也仍是安全处置可用的行动。

## 空间运动程序

用户仍输入自然语言，例如“沿田径场顺时针飞行两圈后返航”或“第二圈逐渐升高，机头始终朝向场地中心”，无需输入坐标、表达式或底层字段。DeepSeek 生成 `motion` 节点，并可将其放入现有条件、分支和循环；本地编译器根据共享地图计算可执行轨迹。

运动路径统一支持三种表达：

- `boundary`：沿实体提供的真实边界或中心线飞行，指定方向、圈数与起止高度；圈数允许 `0 < laps <= 20` 的小数，按实际弧长截取，部分圈的终点不会自动闭合。田径场的显示和规划共用跑道中心线。没有边界数据的地点不能假定为圆形。
- `curve`：以地点的空间锚点为原点，用参数 `t`、`pi`、`sin`、`cos` 和有界四则运算表达三维曲线，可组合八字、螺旋或其他曲线。表达式由受限语法树解释，不使用 `eval`，不运行模型生成的任意代码。
- `polyline`：按顺序连接相对于地点锚点的米制三维点，用于一般折线形状。

相对坐标为 x 向东、y 向南、z 向上，原点高度使用地点作业高度；`boundary` 的高度参数为距地面的绝对米数。默认速度 2.5 m/s、朝向沿运动方向；也可固定机头朝向或持续面向指定地点。机头朝向与平移独立，北为 0°，顺时针为正。未指定的高度和方向使用目录中的默认值。

转场允许安全缩短路径；任务轨迹保持规定顺序和方向，连续跟踪而非逐点停车。进度依据实际运动覆盖的轨迹区段累计，不能凭终点到达确认绕行完成；闭合曲线和重复圈数仍必须经过全部规定区段。避障后继续尚未完成的区段，任务完成记录包含 `completed`、`distance_m`（轨迹覆盖距离）、`total_length_m` 和 `progress`。覆盖距离不是包含所有避障绕行的累计飞行里程。

固定机头或面向目标的轨迹在入场后先停止平移、对准到 2° 内，再开始计入轨迹执行。暂停减速时保留独立航向，恢复不重置已有轨迹和偏差记录。执行证据记录 `heading_samples` 和 `max_heading_error_deg`，从首个轨迹采样核验持续航向；超过 0.2 弧度的误差不能因后续重新对准就被抹去或判为完整成功。

任务复核同样保留已开始轨迹的进度、累计时长与航向误差，允许先补做辅助观测，再安全接回原进度点继续。开始执行的具体轨迹、速度及朝向须保持一致，用户明确修改可以取消；尚未开始的动作仍可调整。完成证据用 `tracking_executions` 关联历次执行实例，避免把中断前的运动遗漏或重飞。

单段运动最多 2048 个采样点、3000 米，边界绕行最多 20 圈，速度范围 0.1–4 m/s；采样密度同时考虑曲线变化，不能通过少量采样漏掉高频轨迹。表达式、轨迹长度、建筑安全间距、限高及避让区均在执行前校验。可表达运动组合不等于具备未实现的传感器、运输能力或任意机动性能。

默认规划阶段由模型主动调用三个通用工具：`query_geometry` 查询锚点、地点范围及附近建筑安全包围盒，也可只传已确认的 `evidence_id` 查询观测物体锚点；返回的 `trajectory_bounds_m` 已包含跟踪余量，`relative_path_offset_bounds_m` 是相对锚点的米制偏移范围，曲线 z 使用此偏移而非绝对高度；`preview_plan` 对完整候选进行编译、独立要求检查及全部转场预检；`submit_plan` 提交本会话中试算成功的候选编号。模型通过同一 JSON 接口选择工具、生成表达式和根据诊断修改候选，适配现有服务商；工具不包含半圈或八字等任务处理器，不执行生成的代码，也不在试算中悄悄修改候选。

每次工具规划最多 8 次模型调用、120 秒墙钟时间，每次调用单独计量。工具在后台工作；新指令、Reset 或关闭会作废会话，已在途请求返回后不再继续调用。建筑碰撞反馈包含节点、位置及膨胀后的障碍包围盒；工具只提供结构化地图，不提供隐藏传感器真值。试算不会飞行，也不证明动态避障或实际任务已经成功；执行前仍复查最新状态。

`motion.within_target=true` 表示整条任务轨迹须位于目录公布的地点矩形范围内，并为跟踪误差留出余量；转场不受这一局部范围限制。执行中若实测任务轨迹离开范围则停止并报告失败，不能用飞到邻楼上方代替在指定场地内飞行。

## 飞行中修改

用户可直接提交“先去图书馆”“取消剩余任务并返航”等调整。新指令解释期间，停止旧任务推进，制动等待并继续本地避障；不重置位置、速度、世界时间、交通种子、轨迹、电量或已完成记录。提取与审查阶段收到原生效指令、独立要求、剩余义务和已产生的证据；计划阶段再结合当前执行上下文，输出完整的新剩余程序。

新程序通过能力、类型和路径检查后一次切换。已经生成的所有分支和循环回边都进行静态预检；解释过程中当前位置变化时，还会检查最新位置是否符合新限制，必要时在后台重新预检，不额外调用模型。如果新限高或新避让区排除了当前位置，则保留原限制安全等待，不直接套用限制使控制器硬停。

每次接受任务或澄清结果递增 `revision`，实际生效计划记录 `plan_revision`。历史记录保留各自修订号、唯一 `execution_id/evidence_id` 和循环次数。新步骤的同名 ID 不会读取旧修订结果，只有明确的历史证据 ID 可用于历史条件。新要求被拒绝时不会自动恢复旧任务；可继续提交调整或要求返航。暂停、重置和换地图会使旧的异步回复失效。

## 执行反馈与任务评估

`review` 使模型能在执行中依据观测重新评估后续任务。用户提出“根据检查结果决定下一步”之类要求时，模型可把评估节点放在观测之后，也可配合分支或循环触发；执行到该节点时，将最新遥测、实际执行证据与尚未完成的任务交给 DeepSeek，由它重新组织剩余程序。条件求值、轨迹跟踪和本地避障仍在本地连续执行。

评估期间维持安全等待，模型的新程序仍须通过能力、类型、空间和路径检查；自主评估必须保留独立任务契约中的剩余动作、地点、顺序、次数、条件、运动路径、朝向、驻留、终态与硬约束。允许重命名步骤、展开有限计次循环以及在必需动作之前加入辅助动作；保留终点但删掉中途巡检同样会被拒绝。条件只要求实际选中的分支，已经完成的次数不会重做；未到达的分支和循环仍必须保留原判断。未限定后续行动的开放任务可以以评估节点结束当前程序，再由模型根据已有观测选择后续程序，无需预设返航终点。每条用户指令最多进行 8 次自主评估，避免无限调用；后续用户修改可以重新安排任务。

执行异常也能触发复核，无需预置 `review`：无效观测先重测、路线失败先本地重规划，连续 25 秒无进展会进入同一恢复通路。每个问题先尝试两次本地恢复，再进行有限任务复核；相同问题按目标和已完成证据去重，事件复核间隔至少 10 秒，超过预算保持安全等待。暂停冻结待复核事件，恢复后继续；用户修改、Reset、终止故障会作废旧恢复请求。本地持续避障不依赖模型返回。

`execution_feedback` 保留关键执行反馈，任务界面沿用现有提示展示解析、评估及执行结果，不另设复杂面板。`goal_state` 记录目标位置、要求的地面／空中状态及是否经过遥测确认。完成提示随实际终态显示降落停驻或保持位置，不一律称为返航完成。

## 能力与资源边界

执行器只接受地图公布的地点、技能、可观测字段和受限空间表达，不执行任意生成代码。结构最多 128 个节点、8 层嵌套，定点动作驻留最长 600 秒；同一任务累计最多 1024 次技能调度、1000 次循环迭代，修改任务不清零预算。达到预算或缺少必需观测时进入安全等待，不能标成成功；此时仍允许修改任务。位置、速度、限高、净空和地表等约束统一作用于所有地点及程序组合。

任务目录发布与本地结构校验共用的 `task_program_schema`，覆盖动作、运动路径、位置控制、条件和循环；语义与几何安全检查继续独立执行。格式错误会提供具体 JSON 路径、缺失或多余字段、允许的字段及类型；复核遗漏或改变未完成任务时也进入同一纠错流程，附带剩余任务与原因。自动纠错将这些诊断连同上一版候选交给 DeepSeek，要求保留原指令及约束并修正完整程序，最多两次。候选在内存中脱敏并限制为 32000 字符，超限时仅回传诊断，不写入运行日志或公开状态；提交新任务、重置或结束解析后清除。

初次生成和两次修正均未通过时显示“生成失败”，无人机保持安全等待，允许直接重试原指令；不会把模型格式错误显示成需要用户补充任务条件。地点不明确、能力缺失和安全冲突仍使用各自的反馈。HTTP 503 等临时传输失败继续采用现有退避重试。

这些限制用于约束程序资源和执行能力，不要求用户按固定句式输入。未说明的可选参数使用默认值；含糊地点、缺少能力或互相冲突的要求会给出具体说明。

## 完整任务验收

首次任务和用户修改都经过三个阶段：从原文提取任务要求、对照原文审查漏项及额外限制、通过工具迭代生成执行计划。前两阶段不读取候选计划或旧执行步骤，只使用能力目录、已接受要求和实际证据；原文引用必须覆盖有效文本。审查退回时重新提取，审核通过后才安排计划，计划遗漏要求也会在起飞前被拒绝并自动纠正。提取／审查与直接返回计划的格式纠错各有最多两次机会；工具会话最多 8 次调用、120 秒，耗尽后不会通过外层重试重置预算；执行中复核耗尽时保留证据并安全等待，不归类为 API 故障。越界诊断返回实际值、含跟踪余量的有效范围及最小修正量，模型据此修改自由执行参数并再次试算。

`requirements` 保存目标、顺序、次数、条件和用户明确的参数；缺省速度、高度、采样数等留给执行计划选择。限高按上界、禁区按包含关系检查；相对升降用 `altitude_delta_m` 表达，逐渐升降另用 `altitude_trend` 表达单调性。仅约束升降量与趋势时，曲线要求可省略 `z`，由模型规划具体高度剖面；试算使用执行编译器同一组采样点检查折线段的高度趋势。显式参考高度与升降量矛盾会在冻结要求前被拒绝。

新提取的曲线／折线要求必须声明 `flexible`：`scale_groups` 中每组轴共享正比例缩放，未指定长宽比例时可分别缩放；`offset_axes` 指定可平移的轴。曲线使用 x/y 与参数区间表达水平参考形状，只有源指令限制具体垂向形状时才固定 z；显式固定的几何可使用空自由度。旧保存的要求仍可读取。变换关系以表达式系数或对应折线点证明，也允许保守的算术等价表达和同向共线细分，未支持的恒等变换或重参数化仍会被拒绝。实际运动、驻留、朝向和落地证据仍须满足完整计划；自主复核只更新执行方案，用户主动修改才更新要求。

完成验收核对实际动作、目标、驻留、落地与运动结果；仅到达终点或执行计划结束不足以判成功。状态中的 task_contract 提供验收结果与剩余任务，界面读取不会推进执行。

来源覆盖检查能发现未引用的原文，不能证明自然语言含义已完整理解；独立审查仍由模型完成。[校园语义任务基准](semantic-benchmark.md) 用独立编写的要求评分，任意表达的理解准确率仍需真实模型评测及人工复核。校园基准可使用 HTML 运动学运行器或 Gazebo＋PX4，任务观测仍为模拟传感器；校园和视觉验证花园的 `visual` 动作支持 Gazebo 原生 RGB-D。

## 验证边界

`tests/test_generic_control_service.py` 用指定足球场指令及篮球场、南广场任务验证落地、不返航、再次起飞、低空停留、执行评估与终态；`tests/test_spatial_control.py` 和 `tests/test_ground_sites.py` 验证共享空间与起降通道。`tests/test_semantic_program.py` 验证程序及证据语义，`tests/test_semantic_updates.py` 使用离线语义响应和实际几何规划、控制器验证修改、循环和返航，`tests/test_frontend_semantic_program.py` 验证任务显示、轨迹进度、通用控制、实测终态提示、执行评估及提交交互；空间编译与连续执行另由对应运动测试覆盖。离线响应证明执行链可处理相应程序，不能代替真实 DeepSeek 对任意自然语言的理解验收。

`python scripts/verify_semantic_program.py` 在实际校园建筑地图中运行计次循环、数值分支、条件退出和途中改派，使用离线接口响应并暂不放入鸟群，以单独验证任务执行；报告默认输出到 `outputs/semantic-program/campus-flights.json`，不接触当前 Flask 服务。

`tests/test_task_protocol.py` 检查共享协议、嵌套字段诊断和默认值；`tests/test_semantic_repair.py` 验证自动纠错、任务之间的候选隔离及候选保密，并使用离线 API 响应完成东侧花园和西侧花园的整圈飞行、返航与降落，防止为单个地点添加特例。

完整契约测试及服务回归覆盖复核纠错、条件与循环续跑、任务切换及独立完成门禁；校园语义基准另检查首轮理解与实测任务结果。

`python scripts/verify_tool_planning.py --output /tmp/tool-acceptance.json` 读取本地 `.env`，真实调用模型验收半圈和八字，并根据实测圈数、机头方向、交叉与两叶面积、升高量、场地范围和返航状态评分。该程序使用 HTML 执行器、固定步长并等待规划，关闭鸟群，仅做功能验收，不作为实时性能或物理飞行基准；`--replay /tmp/tool-acceptance.json` 可在不调用 API 的情况下，用同一模型响应回放任务。输出文件须不存在，不修改网页配置。
